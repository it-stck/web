## Diagnosing and Resolving Replication Issues with Repadmin  

### Common Replication Error Codes and Resolutions  
- **"Replication failure: 80000000"** – Generic HRESULT error. Use `repadmin /showrepl` to identify the affected DC and partition.  
- **"Replication failure: 8009030C"** – `LDAP_SERVER_CANNOT_CONTACT_SERVER`. Verify network connectivity between DCs and ensure DNS resolution is correct. Use `repadmin /replicate <DC> <Partition>` to force replication.  
- **"Replication failure: 8009030A"** – `LDAP_ERROR_UNSUPPORTED_CONTROL`. Check for invalid controls in replication requests. Use `repadmin /forcereplication` to resolve persistent issues.  

### Step-by-Step Repadmin Command Workflow  
1. **Check Replication Status**  
   ```  
   repadmin /showrepl  
   ```  
   - **Output**: Displays replication status, latency, and errors. Look for `*` symbols indicating conflicts, failures, or inconsistencies in replication status.  

2. **Force Replication Between DCs**  
   ```  
   repadmin /replicate <SourceDC> <TargetDC> <Partition>  
   ```  
   - **Example**: `repadmin /replicate DC1 DC2 "DC=Domain,DC=com"`  
   - **Use Case**: Resolve one-way replication failures by manually triggering replication.  

3. **Synchronize All Partitions**  
   ```  
   repadmin /syncall <DC> * /A  
   ```  
   - **Example**: `repadmin /syncall DC1 * /A`  
   - **Use Case**: Force full synchronization of all partitions on a specific DC.  

4. **Force Global Replication**  
   ```  
   repadmin /forcereplication <DC> <Partition>  
   ```  
   - **Example**: `repadmin /forcereplication DC1 "DC=Domain,DC=com"`  
   - **Use Case**: Urgently resolve replication delays or conflicts across the domain.  

### Troubleshooting Tips  
- Use `repadmin /showrepl` first to identify the root cause.  
- Combine `/replicate` and `/forcereplication` for targeted fixes.  
- Always verify results with `repadmin /showrepl` after resolving errors.
