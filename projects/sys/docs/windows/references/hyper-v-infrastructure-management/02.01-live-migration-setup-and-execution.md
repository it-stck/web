Hyper-V live migration enables moving virtual machines (VMs) between hosts with minimal downtime, preserving VM state and connectivity. This process requires careful planning to ensure compatibility, resource availability, and network readiness. Below are the steps and prerequisites for setting up and executing live migration.

---

## Prerequisites for Live Migration  
1. **Host Requirements**:  
   - Both source and destination hosts must run Windows Server 2012 R2 or later.  
   - Hyper-V role must be enabled on both hosts.  
   - Hosts must be part of the same domain or have trust relationships if not in a cluster.  
   - Time synchronization must be configured (e.g., via Windows Time service or NTP).  

2. **Storage Requirements**:  
   - VMs must reside on shared storage (SAN, NAS, or clustered storage) accessible by both hosts.  
   - Shared storage must support live migration (e.g., SMB 3.0 or iSCSI).  

3. **Network Requirements**:  
   - A dedicated migration network or shared network with low latency.  
   - Virtual switches must be compatible (e.g., standard switches, not private or external).  
   - Ensure hosts have sufficient bandwidth to handle VM data transfer.  

4. **VM Requirements**:  
   - VMs must be in a **running** state.  
   - VMs cannot use features like **dynamic memory**, **live storage migration**, or **virtualized SCSI**.  
   - VMs must not be in a **paused** or **saved** state.  

---

## Setup Steps for Live Migration  
1. **Enable Live Migration on Hosts**:  
   - Open **Hyper-V Manager**, select a host, and go to **Virtual Machine Settings**.  
   - Ensure **Live Migration** is enabled under the **Hyper-V Settings**.  
   - Alternatively, use PowerShell:  
     ```powershell
     Set-VMHost -EnableLiveMigration $true
     ```  

2. **Configure Shared Storage**:  
   - Ensure VM VHDs are stored on a shared storage array.  
   - Verify storage access via PowerShell:  
     ```powershell
     Test-VMStorageAccess -Path "E:\VMs\MyVM.vhdx"
     ```  

3. **Set Up Migration Network**:  
   - Assign a dedicated IP subnet for migration traffic (e.g., `192.168.10.0/24`).  
   - Configure network adapters on both hosts to use this subnet.  

4. **Verify Host Compatibility**:  
   - Ensure both hosts have identical CPU features (e.g., same vendor, architecture, and virtualization extensions).  
   - Use PowerShell to check host compatibility:  
     ```powershell
     Get-VMHost | Select-Object Name, CPUCount, MemoryAssigned
     ```  

---

## Execution Steps for Live Migration  
1. **Initiate Migration via GUI**:  
   - In Hyper-V Manager, right-click the VM and select **Move** > **Live Migration**.  
   - Choose the destination host and confirm.  

2. **Initiate Migration via PowerShell**:  
   - Use the `Move-VM` cmdlet:  
     ```powershell
     Move-VM -Name "MyVM" -DestinationHost "TargetHost" -LiveMigration
     ```  
   - Monitor progress with:  
     ```powershell
     Get-VM -Name "MyVM" | Select-Object MigrationStatus, MigrationProgress
     ```  

3. **Monitor Migration**:  
   - Check the **Hyper-V Manager** console for migration status (e.g., "Migrating" or "Completed").  
   - Review event logs for errors (e.g., **Event ID 1246** for migration failures).  

4. **Post-Migration Verification**:  
   - Confirm the VM is running on the destination host.  
   - Validate network connectivity and VM performance.  

---

## Troubleshooting Common Issues  
- **Network Latency**: Ensure migration network has low latency (target < 50ms).  
- **Storage Access**: Verify shared storage is accessible via `Test-VMStorageAccess`.  
- **CPU Mismatch**: Use `Get-VMHost` to ensure hosts have compatible CPU features.  
- **Resource Constraints**: Ensure destination host has sufficient memory and CPU.  
- **Firewall Rules**: Allow ICMP and SMB traffic between hosts.  

---

## Key takeaways  
- Live migration requires shared storage, compatible hosts, and a dedicated network.  
- Use PowerShell for automation and real-time monitoring.  
- Always verify VM compatibility and resource availability before migration.  
- Troubleshoot network latency, storage access, and CPU mismatches promptly.  
- Post-migration validation ensures service continuity and performance.
